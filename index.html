Address (the small data string)

Every image of the chosen size has one address, except the all-white page (see boundary case below). READ computes value = (C·index) mod N; the hex digits of value are the pixels.

Two modes. Colour preview: rescale the image to the page and map it to the 16 palette colours. Lossy — a page of pixels holds only L*4 bits of colour. Write any text into the library

    

      
      
    

    
The text is hidden in the pixel bytes of a chosen page (magic B1 BE + length + UTF-8). The address of that page will always show it. Nothing is stored. The text is found by scanning the pixel bytes of the page the address decodes to.

  






  

    
Self-test

    

    

    
Also runs automatically with ?test=1. Compares the WASM expand/compact against the JS reference, round-trips addresses and images for all sizes, checks the bijection math (C·I ≡ 1 mod N), CRC32 and base32 vectors, embeds and reads messages, encodes and decodes an exhibit PNG and re-derives its address.

  


  

    
How libraryofbabel.app works

    

      
libraryofbabel.app — open source at github.com/tdjsnelling/babel (GPL-3.0). A book is 1,312,000 characters from a 32-symbol alphabet. Constants: N = 321312000 − 1 (written in the README exactly as the all-digit number vvvv…v), C a random number coprime to N, I = C⁻¹ mod N found with the extended Euclidean algorithm. Every book gets a sequential index from its address (room·wall·shelf·book·page).

      
Generate: value = (C·index) mod N. Write value in base-32 with 1,312,000 digits; digit i → alphabet character i. That is the book's text.

      
Search: the same codec backwards. Text → base-32 digits → value; index = (I·value) mod N; index → room/wall/shelf/book/page. Because gcd(C,N)=1, multiplication by C is a bijection mod N, so each index maps to one text and each text maps back to one index. In babel.ts this is mpz_mul by C then mpz_mod for generate, and the same pair with I for search.

      
libraryofbabel.info (Jonathan Basile) uses a different invertible map: a linear congruential step x = (a·x + c) mod m (a⁻¹ again from extended Euclid, Hull–Dobell conditions for the parameters) plus Mersenne-style bit tempering whose shifts are undone in reverse order. Source: github.com/librarianofbabel/libraryofbabel.info-algo (CC BY-NC-SA, a non-commercial license; the algorithm is described here, no code from that repository is reproduced).

      
Pixel Babel (this file) applies the same system to images. Alphabet = 16 palette colors, so a w×w page is L = w² base-16 digits = one number V. N = 16L − 1, C is the first odd integer ≥ 0x9E3779B97F4A7C15 coprime to N, I = C⁻¹ mod N (extended Euclid, plain BigInt; a few milliseconds in the browser). The address string is the index in base32 (RFC4648 alphabet, no padding), fixed width, plus 7 checksum characters (base32 of CRC32 over the index bytes). Length: 59 / 212 / 827 characters for 8×8 / 16×16 / 32×32. Download runs FIND, show runs READ; one codec.

      
Boundary case, shared with the reference implementations, which also lose one book: value V = N (every digit 15, the pure-white page) maps to index (I·N) mod N = 0, outside the 1…N range, so the all-white page has no address. Every other page — 16L − 1 of them — exists exactly once. The self-test checks this.

      
Address guessing. The codec is bijective, so two different images always give two different addresses. Blind-guessing one specific page: 8×8 = 1 in 1664 ≈ 1077; 16×16 ≈ 10308; 32×32 ≈ 101233. The codec is deterministic: the same image always produces the same address.

      
Secret messages. A page is L×4 bits. Those bits can be read as colour indices (an image) or as raw data (a message or file); same bytes, same address. The text feature hides UTF-8 behind a B1 BE magic. The lossless archive stores any file's bytes behind a BA CB header, chained across pages with a CRC32, so download restores the original bytes. No server holds any data; the address and this file are enough to recover the page. Anyone with the address and this file can read it, so encrypt before embedding if you need secrecy, or use your own header so the magic is not obvious.

      
Quality of uploaded images. A colour page shows 16 fixed colours on w×w pixels. The colour round trip is exact; the loss comes from mapping a many-colour photo to 16 colours on a small grid (measured: about 16 dB PSNR at 32×32, per-pixel). Two options, neither changes the bijection: (1) Dither (Floyd–Steinberg) trades flat colour bands for grain that averages to the true colour; reduces banding by about 3× and the output is still one valid page. (2) Lossless archive mode stores the file's real bytes instead of colour, so the download is bit-perfect and CRC-verified; large files chain over pages. Both use the same read/find code.

      
The pixel codec (expand/compact) runs as WASM built at runtime from opcodes in this file and is checked against a pure-JS reference on load; base32, CRC32 and the modular math run in JS for both engines. Addresses are identical either way. Single file, no dependencies. Pages from 8×8 to 32×32.

    

  


  

    
Format spec (v1)

    
SIZES        8×8, 16×16, 32×32 · 16-color EGA palette (index 15 = #FFFFFF)
PIXEL BYTES  byte k holds pixels 2k (high nibble, left) and 2k+1 (low nibble)
PAGE VALUE V = big-endian integer of pixel bytes · N = 16^L − 1
INDEX A      in 1..N · READ: V = (C·A) mod N · FIND: A = (I·V) mod N
C            first odd ≥ 0x9E3779B97F4A7C15 with gcd(C,N)=1; I via extended Euclid
ADDRESS      base32( A as L/2 big-endian bytes , no padding ) + base32( CRC32(A) as 4 bytes )
             = 59 / 212 / 827 chars for 8 / 16 / 32. Case-insensitive; spaces . - ignored.
MESSAGE      pixel bytes at offset o: B1 BE len16BE UTF-8 — located by scanning the bytes
EXHIBIT PNG  color-type 3, depth 4, PLTE = palette, tEXt "Address"; pixels+address in one file
